# square - square.github.io

## Bottom Line
Square's open-source portal: a static directory of the company's public projects, with the homepage generated by a Python script that pulls current project data from the GitHub API into a `repos.json` configuration.

## What It Solves
- Present an organisation's open-source work as a coherent directory rather than a raw repository list.
- Keep project metadata current without editing the site by hand.
- Give external developers one entry point to a company's public work.

## Architecture & Mechanics
- `repos.json` configures which repositories appear and how they are categorised.
- A Python script queries the GitHub API and regenerates the homepage from current data.
- The site is static, with custom images and styling over a directory-style layout.
- Categorisation groups projects rather than listing them flat.

## What Is Inside
- **A Jekyll landing page, and almost all of it is assets** — `repo_images/` (27 `.jpg`), `fonts/` (24 files across `.eot`, `.ttf`, `.woff`), `assets/sprites/`. There is no content directory of substance.
- **What it is for** — an index of Square's open-source projects, rendered as a page. The list is the artefact; there is no data file behind it, so it is not machine-readable.
- **CI is `.travis.yml`**, long dead as a free service.
- **Where the value is:** as an example of an organisational open-source landing page, nothing more. Compare `github - government.github.com`, which keeps its equivalent list as validated data.

## Transferable Capability
**Publish an index of what an organisation maintains, so the boundary of what is supported is visible from outside.** Its own weakness is the lesson: because the list is prose rather than data, it cannot be validated, queried or merged, and it decays quietly. Compare [[github - government.github.com]], which holds an equivalent list as checked data.

**Alternative to:** leaving discovery to search, where abandoned and maintained work look identical. **Applies wherever** an organisation wants outsiders to find its work — and it is worth recording as a demonstration that an index maintained as prose loses to one maintained as data.
